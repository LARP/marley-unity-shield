# Security Policy

## Supported Versions

| Version | Supported          |
| ------- | ------------------ |
| 1.0.x   | :white_check_mark: |
| < 1.0   | :x:                |

## Reporting a Vulnerability

The **Marley Unity Shield** team is dedicated to maintaining high standards of software security and ethical research into reverse engineering resilience. If you discover a vulnerability, bypass, or security flaw within the framework or the runtime hardening modules, please report it responsibly.

### Disclosure Guidelines
- **Do not** open public GitHub issues or public discussions for potential zero-day vulnerabilities or security exploits.
- Please submit your findings via GitHub Private Vulnerability Reporting on the repository `marley-games/marley-unity-shield` or contact the security team directly.
- Include a detailed technical proof of concept (PoC), steps to reproduce, targeted runtime condition (C0–C5), Unity version, and architecture details.

### What to Expect
- **Acknowledgment:** Within 48 hours of initial receipt.
- **Triage & Assessment:** Within 5 business days.
- **Remediation & Advisory:** Coordinated release with CVE assignment if applicable.

## Ethical Research Scope
This project is intended strictly for academic benchmarking, defensive hardening, and evaluation of binary protection mechanisms against unauthorized tampering. Ensure compliance with applicable laws when conducting dynamic instrumentation tests.
